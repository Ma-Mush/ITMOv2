# AGENTS.md — Архитектура проекта Lizard Arena

> **Контракт требований:** [docs/requirements.md](docs/requirements.md)  
> **Style Guide и правила кода:** [docs/style-guide.md](docs/style-guide.md)  
> **Единая команда проверки:** `sh scripts/check.sh` (не менять без согласования)

> **Lizard Arena** — многопользовательская 2D-игра в реальном времени (в стиле Agar.io / Slither.io), где вместо червяков или бактерий по арене бегают процедурно анимированные ящерицы, собирают сочные ягодки для роста и наносят урон другим ящерицам при столкновении.

---

## 1. Концепция и Игровые Правила

| Параметр | Значение | Описание |
| :--- | :--- | :--- |
| **Базовое здоровье / Очки** | **100 HP** | Шкала очков напрямую является шкалой здоровья ящерицы. |
| **Сбор ягод** | **+10 HP / очков** | 1 ягодка моментально добавляет +10 очков и восполняет здоровье. |
| **Визуальный рост** | $S = \sqrt{\frac{\text{Score}}{100}}$ | Радиус головы, толщина сегментов и длина тела масштабируются пропорционально квадратному корню из очков. |
| **Количество ягод на карте** | **600 шт.** | Автоматически восполняются сервером для поддержания плотности карты. |
| **Боевая механика (Урон)** | **Укус головой** | Когда голова ящерицы касается тела или головы соперника, наносится урон: $D = 25 + 10 \cdot (S - 1)$. |
| **Вампиризм / Награда** | **+40% от урона** | Атакующая ящерица поглощает часть массы жертвы при каждом успешном укусе. |
| **Гибель и дроп массы** | $\text{HP} \le 0$ | При гибели ящерица распадается на кластер ягод, которые могут съесть другие игроки. |
| **Ускорение (Спринт)** | $\times 1.6$ к скорости | Активируется по ЛКМ или Space. Расходует 6 очков/сек (доступно при HP > 30). |

## 3. Математика и Кинематика Ящериц

### 3.1. Формула масштабирования
Все размеры масштабируются от текущих очков (здоровья):
$$S = \sqrt{\max(10, \text{score}) / 100}$$
*   **Радиус головы:** $R_{\text{head}} = 18 \cdot S\text{ px}$.
*   **Количество сегментов:** $N_{\text{segments}} = \min(42, \lfloor 14 + (S - 1) \cdot 12 \rfloor)$.
*   **Дистанция между сегментами:** $D_{\text{seg}} = 14 \cdot S\text{ px}$.
*   **Скорость перемещения:** $v = \frac{240}{S^{0.2}}\text{ px/s}$ (более крупные ящерицы становятся чуть массивнее).

### 3.2. Цепная кинематика позвоночника (Verlet Distance Constraints)
Тело ящерицы состоит из $N$ сегментов. Голова движется вперёд с плавным поворотом к целевому углу (`lerpAngle`). Каждый последующий сегмент $i$ подтягивается к предыдущему сегменту $i-1$ с сохранением фиксированной дистанции $D_{\text{seg}}$:
$$\vec{seg}_i = \vec{seg}_{i-1} + \frac{\vec{seg}_i - \vec{seg}_{i-1}}{\|\vec{seg}_i - \vec{seg}_{i-1}\|} \cdot D_{\text{seg}}$$

### 3.3. Процедурная анимация лап и языка
*   **Лапы (4 штуки):** крепятся к соответствующим сегментам тела (передние к сегменту 2, задние к середине туловища). Каждая лапа имеет коленный сустав и 3 когтя.
*   **Диагональная походка (Gait):** фазы шага лап инвертированы по диагонали (передняя левая + задняя правая двигаются синфазно; передняя правая + задняя левая — в противофазе). Скорость шага привязана к скорости движения ящерицы.
*   **Раздвоенный язык:** каждые 3 секунды ящерица высовывает анимированный раздвоенный язык, а во время укуса раскрывает челюсти с зубами.

## 4. Сетевой Протокол и Серверный Цикл

### 4.1. Двухуровневый цикл сервера
1.  **Physics Tick (60 Hz):**
    *   Обновление положений ящериц и ограничений позвоночника.
    *   Обновление деревьев решений ИИ ботов (`BotAI`).
    *   Поиск сбора ягод через `SpatialGrid`.
    *   Проверка коллизий «голова атакующего $\rightarrow$ тело/хвост жертвы».
    *   Регистрация событий урона (`DamageEvent`) и уничтожения ящериц.
2.  **Broadcast Tick (30 Hz):**
    *   Формирование снапшота арены (`WorldSnapshot`), включающего позиции, ягоды, топ-10 лидерборда и события для визуализации.
    *   Отправка по WebSocket всем активным игрокам.

### 4.2. Спецификация сетевых пакетов
*   `ClientMessage`:
    *   `{ type: 'join', name, color, secondaryColor }` — вход в арену.
    *   `{ type: 'input', targetAngle, isBoosting }` — ввод направления мыши и спринта.
    *   `{ type: 'respawn', name }` — перезапуск после гибели.
*   `ServerMessage`:
    *   `{ type: 'init', selfId, worldWidth, worldHeight }` — инициализация мира.
    *   `{ type: 'snapshot', data: WorldSnapshot }` — текущее состояние арены.
    *   `{ type: 'died', killerName, finalScore }` — уведомление о гибели игрока.

## 5. Искусственный Интеллект Ботов (`BotAI`)

В игре непрерывно поддерживается популяция из **14 ботов**. Поведение каждого бота управляется конечным автоматом с тремя состояниями:

1.  **`FORAGE` (Сбор ягод):**
    *   Бот сканирует пространство вокруг себя радиусом 400px с помощью `SpatialGrid`.
    *   Выбирает ближайшую ягодку и направляет голову к ней.
    *   При отсутствии ягод совершает естественное плавное блуждание.
2.  **`ATTACK` (Охота на ящериц):**
    *   Если в радиусе 450px обнаружена ящерица сопоставимого или меньшего размера — бот переключается в атаку.
    *   Бот целится не прямо в голову, а в середину туловища или хвост жертвы.
    *   На дистанции ближе 180px включает спринт для нанесения укуса.
3.  **`FLEE` (Бегство):**
    *   Если приближающаяся ящерица превосходит бота по масштабу более чем в $1.35\times$ — бот разворачивается на $180^\circ$ и убегает с ускорением.
4.  **`Boundary Avoidance`:**
    *   При приближении к красным границам мира (ближе 180px) бот плавно поворачивает к центру арены.

## 6. Процедурный Аудио- и Визуальный Движок

*   **Звуки (Web Audio API):**
    *   Все звуки генерируются процедурно через осцилляторы (`SoundEffects.ts`):
        *   Поедание ягоды — приятный высокочастотный щелчок с частотной модуляцией (420–630 Hz).
        *   Укус соперника — треугольный щелчок челюстей.
        *   Получение урона — пилообразный глухой удар.
        *   Гибель — низкочастотное затухание.
    *   *Преимущество:* Нулевой размер зависимостей, отсутствие битых mp3 ссылок, мгновенный отклик.
*   **Система частиц (`ParticleSystem.ts`):**
    *   Взрывы разноцветных искр при поедании ягод (цвет искр соответствует цвету ягоды).
    *   Красные брызги при укусе.
    *   Всплывающие цифры урона (`-26`) и очков (`+10`).
*   **Динамическая камера (`CanvasRenderer.ts`):**
    *   Плавный зум: чем больше очков у ящерицы, тем дальше отдаляется камера, открывая больший обзор арены.
    *   Миникарта в нижнем правом углу с отображением всех игроков и собственной позиции.

## 7. Подключенные Инструменты, Навыки и Обоснование

### 7.1. MCP-серверы
1. **Собственный MCP (`server/mcp/arena-mcp-server.ts`)**:
   * **Назначение**: Расчёт боевого баланса, урона, вампиризма, визуального скейлинга и параметров ящерицы по авторитетным формулам проекта.
   * **Tools**:
     * `simulate_combat`: расчёт урона ($D = 25 + 10 \cdot (S-1)$), вампиризма (+40%), гибели и дропа ягод при коллизиях `head_to_body` и `head_to_head`. Валидирует входные данные (проверка на положительные числа и допустимые типы столкновений).
     * `calculate_lizard_specs`: кинематические характеристики (радиус головы, число звеньев, дистанция, скорость, зум камеры).
   * **Запуск и тестирование**: `npm run test:mcp` (скрипт `scripts/test_mcp.mjs` проверяет регистрацию тулов, успешный вызов и обработку некорректного входа).
2. **Внешний Playwright MCP (`@playwright/mcp`)**:
   * Подключен для взаимодействия с браузером и визуальной проверки в реальном UI.

### 7.2. Agent Skills
1. **`lizard-arena` (`.agents/skills/lizard-arena/SKILL.md`)** — *собственный skill*:
   * Содержит константы, физические кривые и архитектуру арены.
   * Проверяется скриптом `scripts/test_balance.ts`.
2. **`playwright-expert` (`.agents/skills/playwright-expert/SKILL.md`)** — *готовый skill*:
   * Предоставляет проверенные паттерны E2E-тестирования (отказ от хрупких селекторов, авто-ожидания вместо `waitForTimeout`, POM).
3. **`websocket-engineer`** и **`game-developer`**:
   * Паттерны сетевой сериализации, авторитетного сервера и Spatial Hash Grid.

### 7.3. Lifecycle Hooks и Автоматическая Проверка
1. **`PreToolUse` (Safety Gate — `.agents/hooks/safety-guard.mjs`)**: блокирует деструктивные команды (`rm -rf`, `git clean -fdx`).
2. **`PostToolUse` (Type Verifier — `.agents/hooks/type-verifier.mjs`)**: автоматически запускает `tsc --noEmit` после правок (`write_to_file`, `replace_file_content`), возвращая ошибки типов агенту.
3. **`PreInvocation` (Reminder — `.agents/hooks/reminder.mjs`)**: напоминает правила арены перед вызовом модели.
4. **OpenCode 2 Plugin (`.opencode/plugins/check-after-edit.js`)**: хук `execute.after`, вызывающий `scripts/check.sh`.

### 7.4. Обоснование подключений для ревьювера
* **AGENTS.md**: фиксирует строгий контракт авторитетного сервера и кинематики, устраняя рассинхрон клиента и бэкенда.
* **Skill (`lizard-arena` & `playwright-expert`)**: избавляет от галлюцинаций в математических формулах и предотвращает флакующие E2E-тесты.
* **Custom MCP Server**: даёт агенту готовый инструмент проверки игровых ситуаций без необходимости ручного вычисления формул и запуска всего клиента с сервером.
* **Hook (`type-verifier` / `check-after-edit`)**: обеспечивает мгновенную обратную связь — ошибка компиляции выявляется сразу после правки, а не на этапе коммита.

## 8. Запуск и Тестирование

### Единый раннер проверок
```bash
# Быстрая проверка типов, сборки, формул skill и тулов MCP
npm run check
# или напрямую
sh scripts/check.sh
```

### Комплексный Pre-Commit хук
```bash
# Запускает check.sh + фоновый подъем сервера + полный Playwright E2E тест
npm run pre-commit
```

### Запуск проекта
```bash
# Сборка клиентского бандла
npm run build

# Запуск единого сервера (клиент + WebSocket бэкенд на http://localhost:3000)
npm start

# Режим разработки (Vite + tsx watch)
npm run dev
```

### Запуск тестов
```bash
# Проверка формул собственного скилла
npx tsx scripts/test_balance.ts

# Проверка собственного MCP сервера (успешный и ошибочный вход)
npm run test:mcp

# Запуск E2E Playwright теста в браузере
npm run test:e2e
```
