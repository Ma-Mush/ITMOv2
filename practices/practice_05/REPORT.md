# Отчёт по ДЗ 5: SDD в brownfield-проекте (Lizard Arena)

### Фреймворк

В качестве альтернативы OpenSpec я взял GitHub Spec Kit (`specify-cli`). 

Как я понял, в Spec Kit нет такой строгой системы команд и методов, как в OpenSpec.
Если на паре мы выполняли какие то команды (openspec show CHANGE etc), а в Spec Kit это скорее просто задача контракта устройства файлов. С одной стороны - OpenSpec позволяет лучше контролировать процесс, но с другой - порой слишком усложняет процесс, где агент сам бы мог разобраться, а человек посмотреть в файлике / гите.

### Ревью агентом и матрица согласования:
Обе первичные спеки прогнал через агента-ревьюера. Были найдены ошибки. Все они сведены в единую матрицу и зафиксированы в общем контракте: **[specs/003-contract.md](specs/003-contract.md)**

**Основные конфликты, которые разрулили до написания кода:**
1. **Формат времени:** UI хотел готовую строку `"03:42"`, а бэк слал `survivalTimeMs`. Договорились, что сервер шлёт только сырые миллисекунды, а клиент сам форматирует в `MM:SS`.
2. **Очки при смерти:** Бэкенд по дефолту обнулял `score` при гибели (`hp <= 0`), из-за чего модалка всегда показывала бы унылый `0`. Добавили поле `preDeathScore`, чтобы сохранить финальный честный счёт.
3. **Единицы измерения:** UI ждал `"342 HP"` и `"2.19x"`. Запретили бэкенду слать строки с суффиксами — только числа (`number`), верстка сама дописывает нужные буквы.
4. **Нейминг:** привели к единому виду названия полей (`berriesEaten`, `killsCount`, `damageDealt`, общий тип `MatchSummaryData` в `shared/types.ts`).

### Проверки:
