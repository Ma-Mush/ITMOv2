# Нагрузочное тестирование — план и сценарии (ReAct)

Документ сформирован с использованием цикла ReAct (Thought -> Action -> Observation) на основе анализа исходных файлов Практики 1 (`tests_load.md`, `context.md`, `CASE.md`).

Назначение документа:
- Обеспечить верифицируемый контур нагрузочного тестирования для сервиса AI-ревьюера PR.
- Проверить стабильность работы сервиса при штатном и аномальном трафике.
- Подтвердить соблюдение бизнес-ограничений (API-1, REL-1, SEC-1, OUT-1, OBS-1) под нагрузкой.

Порядок использования:
1. Выбрать сценарий в зависимости от проверяемой гипотезы или этапа релиза.
2. Подготовить нагрузочный генератор (k6 / locust) с эмуляцией diff соответствующего размера и структуры.
3. Провести прогон и занести ссылки на артефакты в колонку Evidence.
4. Сверить факт с колонкой «Допустимый предел». Превышение порогов инициирует баг-репорт.

## Инструменты и сбор Evidence

- Генераторы нагрузки: k6 или locust.
- Инструменты телеметрии: Prometheus, Grafana, Jaeger (трейсинг задержек), Loki (аудит логов).
- Требования к Evidence:
  1. Экспорт отчета нагрузочного прогона (HTML/JSON).
  2. Ссылка на дашборд мониторинга за время прогона.
  3. Трейс задержек или лог проверки контракта/безопасности.
  4. Четкий статус: Pass / Fail с фиксацией выявленных узких мест.

## Критерии приемки

- Обязательные базовые тесты и тесты соответствия правилам (Smoke, Sustained, Payload Boundary, Overflow Rejection, Masking Overhead, LLM Timeout Fallback, Output Conformance, Log Compliance) должны выполняться строго в пределах заданных SLA.
- Исследовательские тесты (Spike, Stress Ramp, Soak) служат для мониторинга запаса прочности и не блокируют релиз, если сбои локализованы и система восстанавливается в заданные интервалы.
