# Нагрузочное тестирование — многоуровневый план и сценарии

Документ описывает гибридную стратегию нагрузочного тестирования, выбранную в результате анализа альтернатив (Tree of Thoughts: разделение на быстрые проверки в CI, предрелизные тесты емкости и периодические глубокие испытания стабильности).

Назначение:
- Разграничить зоны ответственности тестов между пайплайнами (CI/CD, релизный гейт, регламентные ночные прогоны).
- Обеспечить воспроизводимость профилей нагрузки и измеримость результатов (SLO/SLA).
- Исключить субъективность при приемке релизов за счет жестких критериев Evidence.

Порядок использования:
1. Для каждого уровня пайплайна брать назначенный сценарий из таблицы.
2. Проводить запуск через k6 или locust с фиксацией параметров прогона.
3. Обязательно вносить подтверждающие артефакты в колонку Evidence.
4. Считать проверку пройденной только при выполнении всех пороговых условий.

## Инструменты и сбор Evidence

- Нагрузочные генераторы: k6, locust.
- Инфраструктурный мониторинг: Prometheus, Grafana, OpenTelemetry/Jaeger, логи Nginx и БД.
- Требования к Evidence:
  1. Ссылка на постоянный артефакт запуска (HTML/JSON отчет k6/locust).
  2. Ссылка/снимок таймфрейма дашборда Grafana с аннотациями прогона.
  3. Трейс из APM при деградациях p95/p99.
  4. Четкий вердикт: Pass / Fail с указанием узких мест при отказе.

## Критерии приемки

- Тесты уровней 1 и 2 обязательны для блокировки регресса: любой выход за «Допустимый предел» блокирует выкатку релиза.
- Тесты уровня 3 выполняются регламентно (ночные/еженедельные запуски): служат для исследования запаса прочности, обнаружения утечек и настройки алертинга.
