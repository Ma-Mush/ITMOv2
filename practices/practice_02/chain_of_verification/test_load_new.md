# Нагрузочное тестирование — план и сценарии

Документ регламентирует проведение нагрузочных испытаний сервиса, определяет критерии производительности и порядок фиксации результатов.

Цели:
- Предотвращение деградации latency и сбоев при росте нагрузки.
- Определение емкостных лимитов (capacity) и точек отказа (break points).
- Формирование верифицируемой базы артефактов (Evidence) для релизных циклов.

Как использовать:
1. Выбрать нужный профиль нагрузки и запустить тест через k6 или locust.
2. Собрать метрики доступности, времени ответа и утилизации ресурсов.
3. Прикрепить отчеты и ссылки на дашборды в поле Evidence.
4. Сверить факт с колонкой «Допустимый предел». При превышении лимитов оформить дефект с метками узких мест.

## Сценарии нагрузочного тестирования

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Smoke baseline | 10 rps, 1 минута | p95 ≤ 1.0s, p99 ≤ 1.5s, ошибок ≤ 0.5% | Время ответа, HTTP 5xx/4xx ошибки | k6 summary report, Grafana RPS/Latency dashboard |
| Baseline устойчивость | 10 rps, 10 минут | p95 ≤ 1.0s, ошибок ≤ 1%, дрейф p95 ≤ 10% | Стабильность задержек во времени | Locust stats HTML/CSV, график p95 во времени |
| Sustained-50 | 50 rps, 10 минут | p95 ≤ 1.0s, ошибок ≤ 1%, CPU pod ≤ 70% | Задержки, потребление CPU и памяти | k6 report, Grafana Pod Metrics (CPU/RAM) |
| Capacity-100 | 100 rps, 10 минут | p95 ≤ 1.2s, p99 ≤ 2.0s, ошибок ≤ 1%, CPU ≤ 80% | Latency, saturation пула соединений БД | k6 report, Grafana DB Pool Metrics |
| Capacity-200 | 200 rps, 10 минут | p95 ≤ 1.3s, p99 ≤ 2.2s, ошибок ≤ 1.5%, CPU ≤ 85% | Время обработки, паузы GC (garbage collection) | k6 run artifact, метрики runtime GC pauses |
| Peak-500 | 500 rps, 5 минут | p95 ≤ 1.5s, ошибок ≤ 2%, восстановление за ≤ 30с | Поведение на пике, скорость возврата в норму | Locust report, Grafana аннотированный график пика |
| Spike 5× | Скачки 100 → 500 rps (60с полка, 3 цикла) | Ошибок в спайке ≤ 5%, стабилизация p95 ≤ 1.2s за ≤ 30с | Очереди запросов, динамика отказов | k6 spike test results, Ingress queue metrics |
| Stress ramp | Рамп 0 → 1000 rps за 10 минут | Фиксация точки перегиба (p95 > 1.5s или ошибок > 2%) | Максимальная емкость до деградации | k6 ramping summary, таблица точки отказа |
| Soak-60 | 50 rps, 60 минут | Ошибок ≤ 1%, рост памяти RSS ≤ 5%, стабильный p95 | Утечки памяти, файловых дескрипторов, пулов | k6 soak report, Grafana Memory/Leak dashboard |
| Read-heavy | 100 rps, 10 минут (80% GET) | p95 ≤ 1.1s, ошибок ≤ 1%, Cache Hit Rate ≥ 80% | Эффективность кэша, задержка чтения | k6 summary, Redis/Cache dashboard |
| Write-heavy | 50 rps, 10 минут (40% POST/PUT/DELETE) | p95 ≤ 1.5s, p99 ≤ 2.5s, ошибок ≤ 1%, lock wait ≤ 50ms | Блокировки строк/таблиц БД, IOPS | k6 report, PostgreSQL locks / slow query log |
| Payload max | 20 rps, 10 минут (максимальный размер body) | p95 ≤ 1.3s, ошибок ≤ 1%, отсутствие 413/504 | Парсинг body, сетевой throughput | k6 metrics JSON, Nginx ingress access/error logs |
| N+1 / Списки | 20 rps, 10 минут (фильтры и пагинация) | p95 ≤ 1.2s, стабильное число SQL-запросов на endpoint | Число запросов к БД на транзакцию, CPU БД | Jaeger/OpenTelemetry traces, APM query list |
| Cold → Warm | 50 rps, 5 минут (холодный кэш) | Прогрев ≤ 120с, далее p95 ≤ 1.2s, ошибок ≤ 1% | Время прогрева кэша и JIT-компиляции | k6 timeseries log, Grafana Cache Warmup metrics |
| Degradation tolerance | 50 rps, 10 минут (+100ms в upstream БД) | p95 ≤ 1.6s, ошибок ≤ 1%, без каскадных таймаутов | Поведение при деградации внешних связей | k6 fault injection report, APM trace latency |

## Инструменты и фиксация Evidence

- Инструменты нагрузки: k6 или locust.
- Инструменты наблюдаемости: Prometheus + Grafana, Jaeger/APM, логи веб-сервера и аналитика медленных запросов БД.
- В колонку Evidence прикладываются:
  1. Ссылка/файл HTML- или JSON-отчета k6/locust.
  2. Ссылка на дашборд Grafana с фиксацией периода теста.
  3. Трейсы медленных запросов из APM (для сценариев с деградацией).
  4. Резюме прохождения (Pass/Fail) и перечень выявленных ограничений.

## Критерии приемки

- Обязательные тесты (Smoke, Baseline, Sustained, Capacity, Read/Write, Cold start, Soak) считаются успешными только при соблюдении всех порогов из колонки «Допустимый предел».
- Стресс- и спайк-тесты (Spike, Stress ramp, Degradation tolerance) оцениваются по стабильности восстановления и фиксации точки излома.
